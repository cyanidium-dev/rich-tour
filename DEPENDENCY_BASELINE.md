## Данные Sanity и внешние проверки

Аудит `users-production` по текущему `USER_DATA_MASTER_KEY`: 957 документов (955 агентов и 2 агентства), все payload читаются; 0 открытых чувствительных полей, неверных lookup, отсутствующих пар `{plain, hash}` и несовпадений временных паролей. Прямой запуск `npm run users:audit` в текущей среде завершается сетевой ошибкой `fetch failed`; тот же код аудита, переданный Node через stdin, успешно проверил документы. Причина различия способов запуска не установлена.

**Блокер:** публичный dataset `production` всё ещё содержит 954 старые пользовательские записи. Агрегированные публичные запросы подтвердили: `password.plain` и `password.hash` у 953 документов, email у 952, телефон у 952, CRM ID у 953, логин у 2. Значения персональных полей и паролей в отчёт не выводились. По плану эти записи пока оставлены для отката; `users:cleanup:apply` допускается только после публикации финальной версии, успешного production smoke и отдельного решения. До этого критерий отсутствия открытых данных в публичных datasets не выполнен.

Локально Node 24 подтверждён; workflow `.github/workflows/ci.yml` указывает Node 24. Настройки Node в Vercel и защита ветки GitHub не доступны из этой рабочей копии и не проверены. Наличие и восстановимость отдельной защищённой резервной копии master key также не подтверждены. План смены ключа документирован в README; готового rekey-скрипта нет.

Отдельная задача плана по перевыпуску ранее раскрытого `SANITY_API_TOKEN` перед деплоем остаётся открытой; значение токена в этот отчёт не записывалось.

Полный smoke/e2e для desktop и mobile, входа реальных агентов/агентств, кабинетов, форм с успешной отправкой, CRM retry, Sanity-контента и опубликованного `users-production` не выполнен. Он требует интерактивного браузера, тестовых учётных записей и безопасного окна для операций с рабочими системами. Интерактивный браузер в этой сессии был недоступен.

## Отложенные major

`@types/node` 26 и TypeScript 7 отложены: это новые major вне текущего плана, а Node runtime остаётся на 24.x. Peer-предупреждения ESLint 10 оставлены как известная проблема совместимости зависимостей `eslint-config-next`; lint и build проходят, обновление ESLint вне рамок этапа 10 не выполнялось.
