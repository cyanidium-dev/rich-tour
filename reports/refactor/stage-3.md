## Server/Client границы

OrdersContent сохраняет use client для загрузки, состояния фильтров, пагинации и модального окна. Category, OrderItem и DetailsModal используют единый тип сущности; собственной директивы им не добавлено, они находятся под клиентским экраном. Чистое преобразование и схема заказа доступны клиенту через index.ts, серверное чтение — только через server.ts с server-only.

Серверные компоненты Reviews и ReviewsListDesk продолжают серверную композицию. ReviewCard не имеет собственной use client: только разметка и форматирование даты. ReviewsList сохраняет клиентскую границу для пагинации и хука размера окна; ReviewsSwiperMob — для Swiper. Серверные данные передаются им через сериализуемые props. Карточка попадает в клиентский граф только через клиентские списки.

Полные транзитивные графы затронутых клиентских корней записаны в stage-3-client-graph.json: OrdersContent — 19 файлов, ReviewsList — 14, ReviewsSwiperMob — 10. Неразрешённых импортов и серверных модулей в этих графах нет. Проверка production JS нашла 0 совпадений с 8 проверенными приватными значениями окружения; сами значения не записывались.

## Повторная проверка 2026-10-01

Состояние Git проверено повторно: в дереве уже присутствует работа этапов 4/5. Она сохранена; повторная проверка и исправления ограничены этапом 3. Результаты ниже относятся к текущему дереву и дополняют исходный отчёт.

Найдены и исправлены три недочёта:

- В преобразовании деталей туристов и архивной выборке оставался `any`; теперь используются тип CRM-пассажира и выведенный тип заказа.
- `agents` и `skippedAgents` читались через `any` без проверки элементов. Ответ API теперь проверяется целиком в сущности `order`; сохраняются порядок списков, строковое представление ID и прежний fallback пустого списка для отсутствующих или не-массивных полей. Неверные элементы массива вызывают существующее состояние ошибки загрузки.

Добавлены тесты ответа CRM и кабинетов, пагинации на границе 200 записей, дедупликации, сохранения дополнительных полей и параметров запроса. Интеграционные тесты `OrdersContent` с тестовым ответом API проверяют активную, архивную и общую выборки, сортировку по ID, вывод сумм, открытие деталей и вариант агентства с предупреждением о пропущенных агентах.
