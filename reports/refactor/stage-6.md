# Этап 6 — остальные группы ввода

Дата: 2026-10-01. Код этапа реализован; чекбокс открыт до smoke заказов в авторизованном кабинете на desktop и mobile.

Первым действием проверен `git status --short`. В рабочем дереве уже были многочисленные изменения предыдущих этапов и удаления `.idea`; они сохранены. Reset, stash и commit не выполнялись.

Форма обратной связи переведена на react-hook-form/Zod. Сохранены маска телефона, украинские сообщения проверки, сброс, закрытие popup и локальное уведомление; серверная отправка не добавлена. Поиск теперь хранит выбранные ключи в react-hook-form, проверяет месяц через Zod и формирует те же параметры `country` и `month`. Текст в ComboBox остаётся отдельным состоянием, поэтому ввод и выбор отображаются как раньше. Фильтры заказов хранят значения в react-hook-form и применяются к списку сразу после каждого изменения; Zod проверяет значения до передачи родителю. Пустые и частично заполненные фильтры допустимы.

Старые Formik/Yup-импорты, компоненты и вспомогательная функция удалены после поиска по `src`. Пакеты удалены из прямых зависимостей и дерева установки; упоминания Yup в lockfile относятся только к необязательному peer-полю стороннего пакета. Для работы существующего тестового окружения закреплены `vite` и `@testing-library/dom` как devDependencies: после удаления Formik/Yup npm убрал их из неявно установленных пакетов. `npm ls --package-lock-only --all formik yup vite @testing-library/dom` подтвердил состав lockfile.

Server/Client: `CallBackForm`, `SearchForm` и `OrdersFilters` остаются Client Components из-за RHF, состояния и браузерных обработчиков. `SearchInput` вызывается только внутри клиентского фильтра, поэтому собственная директива `use client` удалена. Схемы и функции формирования URL не требуют клиентской границы. [Полный транзитивный граф](stage-6-client-graph.json) содержит 9, 6, 5 и 20 локальных модулей для формы, поиска, фильтров и контейнера заказов соответственно; неразрешённых импортов и серверных модулей нет.

Проверки: `npm run typecheck`, `npm run lint` (3 ранее существовавших предупреждения навигации), `npm run build` (32/32 маршрута), `npm run test` (22 файла, 73 теста), `npm run check:architecture` (0 нарушений), `git diff --check` и `npm ci --dry-run --offline --ignore-scripts --legacy-peer-deps` прошли. Адресные тесты покрывают URL, пустые и неверные значения, немедленное изменение поиска и статуса, очистку фильтра и схему обратной связи.

В production Chrome на 1365×768 и 390×844 проверены выбор месяца, формирование и переход по `/search?month=08`, сохранение месяца после перехода и сообщения пустой формы обратной связи. Снимки: [поиск desktop](stage-6-search-desktop.png), [поиск mobile](stage-6-search-mobile.png), [ошибки формы desktop](stage-6-callback-desktop.png), [ошибки формы mobile](stage-6-callback-mobile.png). Локальная страница не вернула страны и туры, поэтому выбор страны и результаты поиска в браузере не проверены; формат URL страны покрыт тестом.

Открытое ограничение: `/agent` без тестовой учётной записи перенаправляет на `/auth/sign-in` на обоих размерах экрана. Smoke реального списка заказов и его фильтров в браузере не выполнен. Поэтому этап не отмечен полностью завершённым.
